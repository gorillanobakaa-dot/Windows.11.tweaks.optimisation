## v0.1.5-beta: the service profiles check what they assume about your PC

**Module 06 (services): before it changes anything, it now checks what each profile took for granted about the machine it was written on.** The profiles were measured on one ThinkPad, and 18 entries are in them because of a fact about that laptop: no SIM card in use, Linux for Windows (WSL) not installed, nothing shared on the network, not part of a company domain, File History not set up, and so on. On your PC some of those facts can be false, and then the entry is wrong for you.

Now:
- The previews ("2 - Preview LIGHT" to "4 - Preview SUPER"), the apply, and `Test-Services.ps1 -Profile <name>` **name every entry whose fact is not true on this PC**, for example: "Sharing: the profile assumes no folders or printers are shared from this machine, which is NOT true on this machine. It would still disable LanmanServer."
- A fact that cannot be checked is shown as **"could not check"**, never as fine. Whether Microsoft Family parental controls are used is one no script can see, so you are asked.
- These are warnings, not refusals, like the module's other warnings: you decide.
- The cellular, Remote Desktop and domain warnings now cover every entry that depends on them. Before, a domain-joined PC was warned only at SUPER, but MODERATE already disables NcaSvc on the same assumption.

**The module's safety self-test checks two more things (15 sections now):**
- every profile entry whose reason rests on "this machine" names the fact it rests on, so a new entry cannot skip the check;
- no profile disables a service that the hardware buttons of a Lenovo laptop need (the list in `Disable-LenovoServices.ps1`).

**The front page** now says which research documents it links to are not published in this repository yet, and shows the right version.

**Where this came from:** Fieldkit (`fieldkit win11 fit` and `win11 oem`) asked these questions from outside the framework; they are now part of the framework itself.

**How it was tested, and what was not:** the new self-test sections pass (12 checks) under PowerShell 7, and they fail when an entry is removed from the table or a broken check is injected. The checks on a real PC (network adapters, shares, registry) were **not yet run on Windows**; off Windows every one of them answers "could not check", as it should. Run "11 - Test the safety logic" on your PC to confirm.

**Nothing else changes.** No profile lists a different service, and the module writes exactly what it wrote before; it only tells you more before it does.
